# SOC Alert Investigation: Repeated Windows Login Failures

## 1. Alert Summary

On 11 October 2026, Wazuh recorded a level 10 alert at 12:16:45.738, generated by custom detection rule `100120`.

The rule was designed to detect three failed Windows login attempts against the same account within 120 seconds.

The alert involved the Windows 11 endpoint `win11-lab-host` and the local test account `SOC-Lab-Test`.

The initial investigation identified repeated interactive authentication failures. Further verification established that these were deliberately generated as part of an authorised SOC lab experiment.

## 2. Investigation Scope and Environment

The investigation focused on authentication events associated with the local Windows account `SOC-Lab-Test`.

**Lab environment:**
- Windows 11 Home endpoint running the Wazuh agent.
- Wazuh Manager, Indexer and Dashboard hosted on a Linux virtual machine.
- Windows Security Event Logs and Wazuh Threat Hunting used for investigation.

**Detection configuration:**
- Custom rule: 100120
- Parent rule: 60122
- Severity: Level 10
- Frequency: 3 failures
- Timeframe: 120 seconds
- Correlation: Same target username

Three failed authentication attempts occurred within 13 seconds, meeting the custom rule's configured correlation threshold.

## 4. Evidence and Technical Analysis

Windows Security logs were examined using PowerShell, filtering Event ID: 4625 for the investigation period.

The three events shared the following characteristics:

| Field | Value |
|---|---|
| Event ID | 4625 |
| Target account | SOC-Lab-Test |
| Logon Type | 2 — Interactive |
| Source Network Address | 127.0.0.1 |
| Status | 0xC000006D |
| Sub Status | 0xC000006A |

The Sub Status indicates that the account was recognised but an incorrect password was supplied.

Wazuh generated a corresponding level 10 alert under custom rule `100120`, confirming that the repeated authentication failures matched the detection logic.

A separate search for Event ID `4624` found no matching successful login for `SOC-Lab-Test` between 12:00 and 12:30 in either Windows Security logs or Wazuh alerts.

## 5. Assessment and Classification

**Detection classification:** True positive.

**Underlying activity:** Benign, authorised security testing.

The custom Wazuh rule correctly detected the intended repeated-login-failure pattern.

The activity was not classified as a malicious incident because the authentication failures were deliberately generated by the lab operator against a dedicated test account.

No matching successful authentication was identified during the investigated period.

## 6. Recommended Actions and Limitations

**Recommended action:** Close the alert as authorised testing after documenting the evidence. No security escalation is necessary for this known simulation.

In a production environment, similar activity would require verification of user activity, examination of the source and investigation of any subsequent successful logins before deciding whether escalation was necessary.

**Limitations:**

- Testing involved one Windows endpoint and one local account.
- Three failed logins can also result from legitimate user mistakes, potentially creating false-positive security alerts.
- The experiment did not establish whether the rule performs reliably across multiple endpoints or different authentication scenarios.
- The original alert description stated 180 seconds, although the tested configuration used 120 seconds. This description was subsequently corrected, and the updated configuration passed validation.
